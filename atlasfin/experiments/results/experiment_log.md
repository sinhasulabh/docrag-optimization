# Experiment Log

Tracks retrieval-quality experiments on the full 288-doc corpus (`ingest_run_uri:
gs://atlasfin-raw-dev/run=20260808t221108z/`), scored against the 123 FinanceBench gold
questions whose evidence doc is in that corpus (`atlasfin.eval.gold.load_gold_set(doc_names=...)`).
All rows chunk to the same 141,375 chunks unless the row's "knob(s) changed" column says
otherwise (chunking config only changes when explicitly noted). Each row's offline
fingerprint differs whenever parsing/chunking/embedding config differs — see each config
file for its exact fingerprint via `offline_fingerprint()`.

Metrics come from `atlasfin.eval.score.score()` (recall@5/10/20, MRR, precision@5 — see
`atlasfin/eval/metrics.py` for exact definitions). Each row's config lives in
`atlasfin/experiments/configs/`. When comparing two rows, only look at the "knob(s) changed"
column as the isolated variable — everything else in that row's config matches the baseline
unless noted.

The `recall@top_k` column reports recall at the row's own `retrieval.top_k` cutoff (via
`atlasfin.eval.metrics.recall_at_k(..., cutoffs=...)` directly, since `score()`'s default
cutoffs stop at 20) — for `top_k=20` rows this is identical to the `recall@20` column, so it's
only shown when it differs.

| 2026-08-10 | dense + decompose | [`dense_decompose_full.yaml`](../configs/dense_decompose_full.yaml) | `retrieval.query_transform: none → decompose` | 0.293 | 0.398 | 0.520 | — | 0.178 | n/a | Hypothesis: breaking a question into 2-4 sub-questions (one Gemini call), retrieving each separately, and RRF-fusing the results would help the analytical/multi-hop misses (e.g. "what drove operating margin change") that a single query embedding can't represent well. **Worse than doing nothing at all** — every metric dropped *below the untransformed baseline* (recall@5 0.301→0.293, recall@10 0.439→0.398, recall@20 0.528→0.520, MRR 0.208→0.178), and far behind dense+HyDE (0.569 recall@20).
